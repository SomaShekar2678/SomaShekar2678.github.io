## Scientific boundaries

Earth is textured but scene distances and spacecraft size are illustrative, not to scale. Satellite is original representative navigation spacecraft geometry, not a named mission. Its original artistic roll is retained, not an attitude-dynamics simulation. Radio wave overlays are scientific illustrations, not visible light or an EM solver. The spectrum retains the original synthetic noise/CW/chirp model. Array response derives from the existing 4×4 λ/2 steering vectors and conventional/MVDR weights, with radial dB compression and an illustrative morph. Hardware represents processing architecture, not a product board or project photograph. LiDAR is generated by ray/surface intersections in a synthetic environment, not a recorded dataset. Ranging lines are explanatory, not a solved PVT estimate.

## Implemented visual changes

1. **Orbit:** original batched spacecraft geometry, six segmented solar panels with cell/busbar textures, mechanical joints, thermal foil with geometry/bump detail, radiator panels, ceramic navigation apertures and telemetry helices. Earth uses local albedo, cloud and night maps, an analytic sun/terminator, inferred ocean specularity, cloud shadow approximation and thin atmospheric limb. Five continuous wavefront caps use the original radius/time law. Distant stars translate with the camera to remove near-field parallax.
2. **Interference:** the original noise, weak signal, CW peak and chirp formulas now displace a shaded triangle surface with restrained contours and derivative normals. This remains a synthetic spectrum waterfall, not a propagation-field solver.
3. **Array:** ceramic substrates and copper patches, shared PCB/ground plane, fasteners and edge connectors. The original conventional/MVDR computation drives a smoother 144×44 angular grid, lit transparent surface and sparse contour mesh. Normals update only when the existing adaptation morph changes.
4. **Hardware:** a representative architecture board with the same four stage locations and five sample streams. Packages, support memory/clock blocks, decoupling, differential lanes, power rails, vias, connectors and function labels are organized around the signal path. Brushed materials and direct-light shadows add depth. This is not a copy of a KV260/RFSoC commercial board.
5. **Perception:** nearest-hit ray/AABB and ground intersections from seven sensor poses, with 32–56 elevation channels (quality tier), angular sampling, range noise, intensity variation and dropouts. Facades, windows, curbs, lamp posts and road paint are structured geometry. The exact original trajectory and reveal law are retained; a sensor vehicle replaces the arrowhead.
6. **Positioning:** the same Earth maps, marker orientation, four satellite positions and ranging fade; small versions of the same spacecraft replace point sprites.

Global: ACES tone mapping, bounded DPR, a shared 128-pixel PMREM, directional solar/studio light and tier-dependent PCF shadows. Worlds draw only while current or transitioning. Transition portals retain their geometry/rotation but are hidden during dwell to remove unrelated rings from finished shots. Scene order, text, layout, camera stations, view offsets, drift, path interpolation and timeline constants are unchanged.

## Loading, accessibility and resilience

The existing near-viewport dynamic scene import remains. Text is available immediately. Geometry is original code, so no remote GLB/HDR downloads occur. Earth images share one loader across the two orbital scenes. Three.js uploads a world's geometry when first drawn. A failed texture or lost context replaces the canvas with the existing six-panel narrative. Rendered 960×640 WebP posters upgrade the phone/reduced-motion/no-WebGL panels; SVG diagrams remain a second fallback if a poster fails.

The RAF loop still stops offscreen and while the tab is hidden. Sustained slow frames reduce DPR to 0.75 and disable shadows. All owned geometry, materials, textures, reflection target and shadow targets are disposed, followed by renderer/context teardown. A rendering harness observed geometry allocations return from 63 to 0 after all six scenes and disposal; renderer statistics retain one internal texture slot after teardown, so a zero-texture count is not claimed. The WebGL context is explicitly released.
