# Portfolio Repository Instructions

## Mission
Build an original, premium, technically sophisticated portfolio for Somashekar Reddy Nakka, using Lusion (https://lusion.co/) as a visual and interaction-quality reference.

## Non-negotiable requirements
- Inspect the repository and existing changes before editing.
- Preserve useful existing code and avoid unnecessary rewrites.
- Verify professional claims against supplied documents and code.
- Never fabricate achievements, performance numbers, credentials, or project status.
- Distinguish research, simulation, prototype, hardware validation, and production deployment.
- Build a complete responsive website, not a static mockup.
- Ensure all buttons, links, navigation, and interactive controls work.
- Support keyboard access, reduced motion, and WebGL failure fallbacks.
- Keep project content editable independently of the presentation layer.
- Avoid unnecessary dependencies and unoptimized assets.
- Never publish secrets, credentials, or confidential employer information.

## Engineering standards
- Use TypeScript and meaningful component boundaries.
- Follow the repository's existing framework and package manager where practical.
- Use proper cleanup for WebGL resources, event listeners, and animation contexts.
- Keep rendering loops efficient and avoid unnecessary React state updates.
- Use semantic HTML and accessible controls.
- Validate the production build and available automated tests.
- Test the rendered website at desktop and mobile viewport sizes when browser tools are available.
- Fix observed defects instead of merely documenting them.

## Completion report
Before finishing, report:
1. Features implemented.
2. Files added or changed.
3. Build, lint, type-check, and test results.
4. Browser and viewport testing actually performed.
5. Known limitations.
6. Missing content or assets requiring the owner's input.
7. How to run and deploy the application.

Never report a check as passed unless it was actually executed successfully.
